# Changelog

## 1.5.0 — 2026-10-25

- Add the **Run & Support (SLA)** report, with the redmine_sla plugin: for each SLA type,
  the respect rate of the delays that ended in each period, overruns and their average
  size, respect by priority (or by the custom field value that sets the term), time
  used against the term, and the delays running today. Figures are read from the SLA
  plugin's cache; a delay ends when the issue last leaves the statuses in which it
  elapses. The family needs the *View SLA* permission.
- Issue lists get two filters per SLA type, used by the report's clicks: *SLA …: end of
  the delay* and *SLA …: time used against the term*.
- The help page explains SLA delays.

## 1.4.1 — 2026-10-25

- Fix the "Translation missing" labels of the report's date options on Redmine 7.0,
  which no longer defines `label_date_from` and `label_date_to` (#7). Tests now
  detect missing translations whatever their case.

## 1.4.0 — 2026-10-25

- Reorganize the project's Reporting settings tab into vertical sub-tabs: Displayed
  reports, Time unit, Run / Build trackers, SLA statuses (with the SLA plugin) and
  Contracts. Each one is saved on its own; saving returns to the same sub-tab.
- Replace yearly credit policies with **credit contracts**: dates of any length, one or
  more trackers, optional subprojects (the closest contract wins), and credit split
  into envelopes by activity and public/private issues, with dated refills and
  adjustments. **Renew** prepares the next contract and can carry the balance over or
  deduct the overrun. Credit policies and refills are dropped by the migration.
- Consumption works contract by contract: summary by contract and envelope, how
  finished contracts closed, and the time outside contracts (or covered by a parent's).
  Credit figures no longer depend on the reader's issue visibility.
- Contract buttons and a private issues switch filter the whole report; both are also
  native filters of Redmine's issue and time lists, used by chart clicks.
- Add a help page for project members (`/projects/:id/reporting/help`), linked from the
  report and the settings, with short explanations on hover.
- REST API: `credit_contracts` replaces `credit_policies`. Redmine Mirror: the
  *Reporting credit contracts* module replaces *Reporting credit policies* and maps
  activities too.

## 1.3.1 — 2026-10-23

- Fix chart clicks opening an empty issue list when tracker, priority or status names
  are translated or decorated by another plugin (e.g. Localizable): selections now
  send record IDs instead of displayed names. Detail links no longer accept name
  parameters (`tracker`, `priority`, `status`, `activity`, `user`).
- Use straight apostrophes in the French translation.

## 1.3.0 — 2026-10-18

- Add a read-only REST API for a project's reporting settings and credit policies.
- Add Redmine Mirror modules copying the reporting settings and credit policies from
  another Redmine. They load only when Mirror is installed.
- Fix "already initialized constant" warnings at boot when `plugins/` is a symlink
  (e.g. a Capistrano shared directory): the plugin files were loaded twice.

## 1.2.2 — 2026-10-15

- Add a step-by-step configuration guide (`doc/CONFIGURATION.md`) whose screenshots
  are regenerated by a browser test (`test/documentation/run.sh`).
- Fix the demo generator leaving the parent project's issues dated on the day of
  generation instead of spreading them over the last 12 months.
- Write the demo content in English; the *Évolutions* subproject becomes *Product*.
  Reseed a fresh database: on one seeded by an earlier version, a new run adds the
  English records next to the French ones.

## 1.2.1 — 2026-10-03

- Add the Reporting logo to the README and dashboard title.
- Add localized Magnific/Flaticon credits and retain image attribution with the assets.

## 1.2.0 — 2026-10-03

Workload & Team:

- Add a RUN/BUILD hours split with unclassified and issue-less categories, percentages
  and native time-entry drilldowns over the selected period.

- Show current open issues and calculated remaining effort by assignee, including
  groups, locked users and unassigned issues; flag missing estimates.
- Show period-based logged time by contributor across all trackers, with native
  list drilldowns using identities rather than display names.
- Respect issue/time visibility independently, including time-only configurations
  and project-level restrictions on remaining-effort calculations and their lists.
- Keep capacity planning out of this first version; no availability is inferred.

## 1.1.0 — 2026-10-03

Build & Projects:

- Add a period-based Burnup by version, replaying membership changes and status
  transitions, including unassignment and reopenings, with native historical
  issue-list drilldowns and viewer-time-zone boundaries.
- Keep future periods out of the Burnup and document missing-history fallbacks.

- Enable the Build family with its own tracker scope; an empty classification
  stays empty and excludes unassigned time.
- Show current open/closed issues, overdue issues and effort by version, including
  unversioned issues, with native issue-list drilldowns and permission-aware time data.
- Preserve the family when applying filters and opening detail lists; support
  projects that enable Build without Run.

## 1.0.0 — Unreleased

Initial Run reporting release: issue flow, activity, time credits, backlog and
performance; project settings, subprojects, native Redmine filters and drilldowns;
English and French UI; bundled Chart.js.

Release hardening:

- Authorize report JSON and project credit scopes, not only visible tabs.
- Reconstruct backlog status from issue journals, including reopenings, with
  matching native issue-list filters and user time zones.
- Compute consumption over the selected period: credit carried over to its first
  day, credits granted in it, time charged over it, credit left at its end. Time
  logged before the contract start is not charged.
- Keep independent credit balances and contract starts at every depth of the project tree.
- Treat each subproject as a credit account of its own and add accounts up, so the
  summary by project, the totals and each subproject's report agree.
- Separate the provider banner from the client consumption figures, with distinct
  labels. The banner's estimated, done and left-to-do figures cover the same filtered
  issues: estimated − done = left to do (open issues) + gap on closed issues.
- Convert each project's consumption with its own inherited hours-per-day setting.
- Reject invalid dates and more than 600 periods before allocating report data.
- Keep demo accounts locked with random passwords, require explicit disposable
  development/test usage, reject unrelated projects and account collisions.
- Keep flow/backlog legends below charts, with sequential flow numbering 1.1–1.6.
- Split collaborator bars by activity with shared colors, hour tooltips and exact
  collaborator/activity drilldowns, including distinct users with the same name.
- Explain consumption legends on hover and add descriptive chart subtitles.
- Move dashboard descriptions and links into DashboardPresenter with explicit
  dependencies; keep formatting/icon helpers independent of controller state.
- Keep date boundaries in Ruby, presentation outside ReportingQuery, and inherited
  settings writes in the model; use prefix sums for historical spent time.
- Add regression/security/browser tests and a Docker/GitHub Actions matrix for
  Redmine 5.0–7.0, SQLite, PostgreSQL, MariaDB, MySQL and SLA coexistence.

SLA reports, Build & Projects and Workload & Team are outside this release.
